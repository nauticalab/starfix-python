# FixedSizeList data in starfix-python (ITL-927)

**Date:** 2026-11-11
**Issue:** ITL-927
**Repos:** nauticalab/starfix (Rust, authoritative), nauticalab/starfix-python (this repo)
**Status:** Layout confirmed by the maintainer on 2026-11-11; ships in 0.5.0.

## Source of truth

The layout is starfix's `docs/byte-layout-spec.md` (Section 3.2, Example 3b) and its design
`docs/metamorphic/specs/2026-11-11-fixed-size-list-design.md`. The 73 `fsl_*` vectors and 34
relations of `tests/golden/format2_v0.5.json` are generated by Rust and copied here byte for
byte. This note records only the Python-specific decisions.

## Layout (summary)

- A fixed-size-list node's entry is its effective validity if the field is nullable and empty
  otherwise: no lengths digest (`n` is in the schema digest) and no values.
- Its element node `p/` gets the `n` items of every effectively valid slot, in order. Items of
  slots that are null (own validity, or masked by a null enclosing struct) and child positions
  past `len * n` are never visited. Struct masking restarts below the list, as for List.
- A null of a non-nullable element under a null slot is accepted; a visible one is rejected.

## Implementation (`src/starfix/_format2.py`)

- `_Entry` kind `fixed_size_list`: validity only.
- `_visit_fixed_size_list_items`: slot `i` covers
  `arr.values[(arr.offset + i) * n, (arr.offset + i + 1) * n)`, because pyarrow's
  `FixedSizeListArray.values` **ignores the array offset**. The items of all slots are one
  zero-copy slice of the child.
  - No null slot (`present is None`) or `n = 0`: the slice is visited once, without any
    selection. No per-item index, mask or copy is built (pinned by
    `test_fixed_size_list_without_nulls_builds_no_item_index`).
  - Otherwise slots are visited in chunks of about `_ITEM_BUDGET` (1M) items. A chunk without
    elements is skipped; a chunk of elements only is visited without a selection; any other
    chunk is visited with the slot bits repeated `n` times as the item selection, which the
    existing select-aware code applies to every node below (validity, non-nullable check,
    lengths, values).
- The repeated bits come from `take(bits, list_parent_indices(FixedSizeList<null>[n]))` over
  a validity-free list of nulls: `list_parent_indices` on the real array **skips null slots**
  (pyarrow 19 to 26), and `flatten()` skips own-null slots but not struct-masked ones, so
  neither is used on the hashed array.
- Leaf values below are hashed by the existing code: fixed-width values through the zero-copy
  unsigned-integer / `FixedSizeBinary` view, so no kernel of the logical type is needed (pyarrow
  19 and 20 have no `filter` kernel for decimal32 / decimal64).
- A dictionary of fixed-size lists is decoded per row with `take` before it is traversed (as
  for lists and structs); hidden child nulls are not validated.

## Tests

- `tests/test_golden_parity_format2.py`: all 496 vectors and 148 relations, no skips. The IPC
  payloads are read without full validation (the hidden-null vectors hold nulls of
  non-nullable fields under null slots).
- `tests/test_format2.py`: spec Example 3b byte for byte (record batch and `hash_array`), the
  non-nullable entry, `n = 0`, slices and trailing child positions on locally built arrays
  (IPC normalizes both, so golden vectors cannot pin them), struct masking at two depths with
  a different offset at every level, non-nullable slots and items, dictionary of fixed-size
  lists, chunked item selection at any chunk size.
- `tests/test_format2_type_matrix.py`: fixed-size lists (`n = 0, 1, 2`, a null slot, trailing
  child positions) of every supported leaf type, nested in list / struct / dictionary and
  containing struct / list / fixed-size list, each compared with a reference holding other
  content under the null slot and no trailing positions, through `hash_array`, record batch
  and stream, sliced and chunked. CI runs it on pyarrow 19.0.0, 20.0.0 and the latest.
- A differential run against the Rust branch (random fixed-size-list tables via IPC) is
  reported on the PR; it is not part of the repository.
