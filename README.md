# starfix-python

Pure-Python implementation of the [starfix](https://github.com/nauticalab/starfix) Arrow logical hasher.

Produces stable SHA-256 hashes of Arrow schemas, tables, record batches and arrays that are:

- **Byte-identical to the Rust implementation**: every vector of the shared golden file
  (`tests/golden/format2_v0.5.json`, generated by Rust) is matched.
- **Column-order and struct-field-order independent** by default. Both orders can be made part
  of the hash (see [Options](#options)). Nothing else is reordered: row order and list element
  order are always hashed.
- **Batch-split independent**: splitting rows into batches, slicing, or adding empty batches does
  not change the hash; adding or removing rows does.
- **Lossless**: a null struct differs from a struct whose fields are all null, null rows are
  counted, every list records its lengths, and the row count is hashed.

> **Hash format 2 (starfix 0.5).** Every hash starts with the 3-byte format number `00 00 02`.
> All hashes differ from those of starfix 0.4 and earlier (format 1, `00 00 01`); see
> [Hash format](#hash-format).

## Installation

```bash
pip install starfix
```

## Usage

```python
import pyarrow as pa
from starfix import ArrowDigester

schema = pa.schema([
    pa.field("id", pa.int32(), nullable=False),
    pa.field("value", pa.float64(), nullable=True),
])

# Hash a full table
table = pa.table({"id": [1, 2, 3], "value": [1.1, 2.2, 3.3]}, schema=schema)
digest = ArrowDigester.hash_table(table)          # 35 bytes: 00 00 02 + SHA-256

# Streaming: feed record batches incrementally (same hash as hash_table)
digester = ArrowDigester(schema)
for batch in table.to_batches():
    digester.update(batch)
digest = digester.finalize()

# A schema, a single record batch, or a single array
ArrowDigester.hash_schema(schema)
ArrowDigester.hash_record_batch(table.to_batches()[0])
ArrowDigester.hash_array(pa.array([1, 2, 3], pa.int32()))
```

## Options

Keyword-only, all `False` by default, the same names as the Rust `HasherConfig` fields, accepted by
`ArrowDigester(...)`, `hash_schema`, `hash_record_batch`, `hash_table` and `hash_array`
(`hash_array` has no `include_metadata`).

| Option | Effect |
|---|---|
| `ordered_columns` | The order of the top-level columns is part of the hash. |
| `ordered_struct_fields` | The order of struct fields, at every depth (struct children, list elements, map keys and values, dictionary values), is part of the hash. |
| `include_metadata` | Schema- and field-level Arrow metadata is part of the hash. A schema without metadata hashes the same either way. |

```python
# A DataFrame-like value whose column order and struct field order are part of its identity
digest = ArrowDigester.hash_table(table, ordered_columns=True, ordered_struct_fields=True)
```

- Leave the order options off to identify *data* independent of how columns or struct fields
  happen to be ordered. Turn them on when order is part of the value's identity, as for a
  DataFrame, or a `pa.StructArray` whose type `struct<a, b>` differs from `struct<b, a>`.
- Hashes taken with different order options never coincide, even when order cannot matter.
- With `include_metadata`, metadata is keyed by each field's node path (column `c`, struct
  child `c/x`, list element `c/`, map key and value `m//key` and `m//value`). Extension types
  are hashed as their storage type; with `include_metadata` their `ARROW:extension:name` and
  `ARROW:extension:metadata` are hashed too, including for extension types registered with
  pyarrow.

## Rejected inputs

`ValueError` is raised, in every mode, for:

- a schema in which two nodes share a path: duplicate column names, duplicate field names
  within a struct, or a name containing `/` that aliases another node (a column `"a/b"` next to
  a struct column `a` with a child `b`). A `/` that aliases nothing (`"km/h"`) is fine;
- `ListView`, `LargeListView`, `Union` and `RunEndEncoded` types;
- hashing data of a schema that contains `Null`, `FixedSizeList`, `Map`, `Interval`,
  `Utf8View` or `BinaryView` (their schemas hash; their data does not), whatever the number of
  rows;
- a non-nullable field holding a null that no enclosing struct null explains;
- streaming: a batch whose schema differs from the digester's. Physically different but
  equivalent types (`Utf8`/`LargeUtf8`, `Binary`/`LargeBinary`, `List`/`LargeList`, dictionary
  and plain values) are accepted; reordered columns or struct fields are accepted unless the
  matching order option is on.

## Hash format

The byte layout is specified in starfix's `docs/byte-layout-spec.md`. The first three bytes of
every hash are the format number:

| Format | Prefix | starfix | Notes |
|---|---|---|---|
| 1 | `00 00 01` | ≤ 0.4 | Lost information for some inputs (Booleans, nullable structs, lists of nullable lists or structs, row counts, and in Python a list of numeric dictionary values). |
| 2 | `00 00 02` | 0.5 | Lossless layout, the two order options, rejections in every mode. |

Format-1 hashes can be computed with starfix 0.4 (`pip install "starfix<0.5"` in a separate
environment). Starfix 0.5 computes format 2 only.
