# Changelog

## Unreleased (proposed 0.5.0)

### Changed — hash format 2 (every hash changes)

starfix-python now computes hash format 2, byte-identical to the Rust starfix crate 0.5. The
3-byte prefix of every hash is `00 00 02` (format 2); starfix-python 0.4 and earlier produced
format 1 (`00 00 01`). **Every hash changes**, and a format-1 hash can always be told from a
format-2 hash by its first three bytes. Format-1 hashes can be computed with starfix 0.4 in a
separate environment. Specification: starfix `docs/byte-layout-spec.md`.

### Fixed — information losses of format 1 (ITL-898)

These inputs collided, or hashed differently depending on batch boundaries, in format 1:

- Booleans were bit-packed per call without a count (`[true]` == `[true, false, false]` in a
  one-column non-nullable table; batch splits changed the hash). Now one byte per valid value.
- A null struct equalled a struct whose fields are all null, and null struct rows vanished
  under non-nullable fields. Now every nullable node records its validity.
- A list whose element is a nullable list lost its own lengths, and a list of nullable structs
  did not distinguish a null element. Now every list records its lengths and every nullable
  element its validity.
- The row count of zero-column tables and empty structs was not hashed. Now it is.
- Python only: a list of dictionary-encoded fixed-width values (for example
  `list<dictionary<int32, int64>>`) hashed the dictionary indices instead of the values.

### Fixed — Python/Rust differences of format 1

All are gone in format 2: map schemas (the value type and `keys_sorted` were not hashed),
non-ASCII struct field names in `hash_array`, metadata paths of map fields, schemas of `Null`,
`Interval`, `Utf8View` and `BinaryView` types (they raised), and the streaming schema check.

### Fixed — performance (ITL-908)

Hashing a list column took time quadratic in the number of rows (every row copied the whole
child values buffer). Format 2 hashes every column type in linear time, working on Arrow
buffers: at 1M rows, `list<int32>` takes about 20 ms instead of an estimated 90 s.

### Added

- Keyword-only options `ordered_columns` and `ordered_struct_fields` on `ArrowDigester(...)`,
  `hash_schema`, `hash_record_batch`, `hash_table` and `hash_array`: make column order and
  struct field order (at every depth) part of the hash. Default off.
- Extension types are hashed as their storage type; with `include_metadata`, their
  `ARROW:extension:*` keys are hashed, also for types registered with pyarrow.
- Golden vectors `tests/golden/format2_v0.5.json`, generated by Rust and asserted in full.

### Changed (breaking)

- In every mode, `ValueError` is raised for schemas with duplicate or `/`-aliased field paths;
  for `ListView`, `LargeListView`, `Union` and `RunEndEncoded` types; for hashing data of
  `Null`, `FixedSizeList`, `Map`, `Interval` and view types (previously `NotImplementedError`
  or accepted); for a non-nullable field holding a null that no enclosing struct null explains;
  and for a streamed batch whose schema differs from the digester's.
